# Jump

统一策略中的条件跳跃任务，只使用 `JUMP_20` / `JUMP_40` 两种跳高模式，独热编码分别为 `[1, 0]` / `[0, 1]`。高度模式与地形分别采样，每种跳高都训练平地跳跃和跳台阶；平地是地形类型，不占独热编码维度。各高度模式的概率、目标、距离表和奖励列表均按此顺序配置。原 flat 独热类别及其专用静止跳采样参数已移除。

`jump_modes.mode_probabilities` 控制两种跳高的采样权重；`jump_modes.platform_probabilities=[0.5, 0.5]` 分别控制 JUMP_20 / JUMP_40 采样台阶的概率，其余回合采样平地。每种高度都有独立的平地和台阶通道，共四条通道，台阶分别为 20 cm / 40 cm。`platform_enabled` 可由课程关闭某种高度的台阶，此时该高度只采样平地。独热编码只表示跳高，不包含地形，地形由实际场景和 ToF 感知。

模式 one-hot 和四维相位输入只持续到 takeoff + flight 结束，默认在跳跃触发后的 0.60 s 同时归零。landing 继续执行完整回合、结算奖励并参与 PPO；任务内部模式编号继续用于落台几何和成功判定。

- `config.py`：模式比例、阶段时长、距离参考上下限、起跳距离表、奖励和课程。
- `buffers.py` / `reward_state.py`：回合状态、连续腾空确认、峰值与落地结算。
- `task.py`：阶段更新、命令、终止和公共环境 hook。
- `approach.py`：空旷区域加速、达速确认及保留物理状态的起跳位置切换。
- `rewards.py`：任务奖励。
- `terrain.py`：任务专用平台通道和模式分配，复用 `terrains` 的公共几何接口。
- `geometry.py` / `height_reference.py` / `phase.py`：几何、轨迹与阶段编码。

jump 与其他任务共享观测、动作和 PPO。每回合先从静止出生在空旷跑道（默认 x=-6、y=-4，地面 z=0），只给行走速度和站立高度命令，jump 模式及阶段编码为零。同一策略实际加速，速度误差不超过 0.15 m/s、双轮接地且姿态/高度稳定连续 0.15 s 后，保留当前高度、姿态、关节状态和全部实际速度，将小车平移到对应通道的指定起跳距离，再输入模式 one-hot 与 t=0 阶段编码。起跳距离由目标速度表及抖动决定。

两种模式共用 `get_cfgs()` 中的 `jump_height_reference`：`min_distance_m`（当前 0.22 m）、`max_distance_m`（当前 0.38 m）和独立的收腿时长 `retract_duration_s`（当前 0.20 s）。距离指 base 原点到左右轮底的平均竖直距离，独立于机身跳高和台阶高度。参考值在 `jump_phase_durations_s.takeoff` 期间从最低平滑升至最高，随后在 `retract_duration_s` 内从最高平滑降至最低，完成后保持最低；两段均使用五次平滑插值，边界速度和加速度为零。当前在 0.00 / 0.20 / 0.40 s 分别为 0.22 / 0.38 / 0.22 m，之后保持 0.22 m。改变 flight 时长不改变收腿速度；若收腿时长超过 flight，则收腿继续到 landing，相位和独热编码仍按 takeoff + flight 归零，完整回合结束时参考命令终止。训练与交互评估使用同一函数，不再配置逐模式轨迹节点。旧存档缺少收腿时长时，沿用该存档的 flight 时长；缺少距离上下限时，从旧节点提取最低/最高值。

跳跃课程起始只采样 `JUMP_40` 平地跳高；任务课程第 500 轮开放台阶采样，第 1000 轮按 `JUMP_20:JUMP_40 = 1:1` 混合。开放台阶后，每种高度默认各有 50% 平地和 50% 台阶回合。两种模式都从静止开始实际加速到各自目标速度。

跳跃的 1.1 s 计时从移动完成后开始，加速时间不占用跳跃时长。相位输入只保留 `[sin(πp), cos(πp), sin(πp/2), cos(πp/2)]` 四维，`p = t / (takeoff + flight)`；默认归一化时长为 0.60 s，进入计划 landing 后全部归零。landing 的奖励、训练样本和 0.50 s 持续时间仍正常保留，完整回合仍为 1.10 s。切换不产生 done、不重置 GRU，保持动作延迟历史；下一拍观测前立即刷新 ToF 测距历史。助跑仅运行同一策略推理，不结算奖励，不参与 PPO 更新、GAE、观测归一化统计或跳跃课程样本计数。达速动作仍属于助跑；只有接收到模式 one-hot 与 t=0 阶段编码后产生的动作及后续跳跃轨迹进入训练。GRU 保留助跑结束时的隐状态，训练从该隐状态开始，不回放或反向传播助跑观测；物理 reset 的 done 仍会重置 GRU。没有 teacher 或独立 runner。

速度跟踪、机身平衡、机身接触、腿部对称、关节速度、动作变化及腿部限位奖励在跳跃期间生效；跳跃专用奖励按各自阶段门控结算。权重由 `config.py::_get_reward_cfg()` 及课程配置提供。动作变化使用公共 `wheel_action_rate` / `leg_action_rate`，基础权重分别为 -1 / -0.1；旧存档的 `action_rate` 仍可加载。助跑专用的 `base_height` 和 `wheel_airborne` 已移除。加速 5 s 未达标则 reset，该助跑回合不产生训练奖励或 PPO 样本；超时、速度容差、站稳时间及出生点由 `config.py::get_approach_cfg()` 配置。日志的 `jump_started` 和 `approach_duration_s` 可区分未达速与跳跃失败。

奖励量级对齐 locomotion：基础速度跟踪各 +2/s、腿部对称奖励 +1/s、平衡权重 -5、机身接触 -10/s。持续跳高项降低到 1～10 的权重，落稳奖励从 5/s 逐步升至 10/s；落稳统一由 `landing_stability` 给分，避免重复结算。除 `death` 不乘 dt 外，jump 事件也乘控制周期：默认 dt=0.01 s 时，合格起跳 +1，基础达标峰值累计 +3，任务成功 +15，任务失败 -10，异常终止另扣 death=-100。峰值和起跳速度项仍允许超目标增长，权重调整后应结合成功率与超高幅度继续观察。

根配置默认按 locomotion:jump=2:1 分配环境，8192 个环境中约 2731 个用于 jump。助跑不产生有效训练样本，因此 jump 的 PPO 样本比例低于环境比例。任务课程仍以 8192 个环境的有效控制步折算轮数；1500 / 3000 的阶段阈值在 1/3 配额下至少需要约 4500 / 9000 个全局轮次，实际还会因助跑而延后。

所有任务和跳跃模式使用根配置的同一组电机参数：默认腿部 kp=50、kd=2，轮部 kd=0.3，腿部/轮部力矩限幅为 40/5。任务、课程和交互控制不能覆盖这些标称值。共享域随机化仍按统一规则调整各环境的实际增益与电机强度。

通过统一 `eval.py --terrain plane` 连续操纵同一个策略：1/2 选择 `JUMP_20`/`JUMP_40` 编码，J 在当前位置启动跳跃命令，完成后继续操纵，不触发任务成功/失败复位。入口和网络约定见 [框架说明](../../README.md)。
